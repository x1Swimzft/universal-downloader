## Why this base

The brief references `85f139c`, but that commit predates v0.6.0. The current branch already ships:

- history search, delete, and clear;
- queue pause/resume/retry/clear-finished and transient retries;
- concurrency from `1` to `5` (default `2`);
- playlist and multi-link preview with selective enqueue;
- updater wiring and the v0.6.0 release.

Rewinding to `85f139c` would discard verified work. This plan therefore keeps v0.6.0 and adds only the missing capabilities. Existing concurrency and multi-link code is extended, not rebuilt.

## Outcome

Users can paste a Spotify or Apple Music track, album, or playlist, choose tracks, and receive tagged audio files. Playlist/album downloads can be grouped into a sanitized subfolder with track-numbered names. Audio filenames follow a preset template. Twitch, Kick, Bilibili, Reddit, Pinterest, Vimeo, SoundCloud, and Bandcamp links continue to flow through yt-dlp without a domain allowlist.

## Non-goals

- No Spotify or Apple Music SDK, API key, login, or DRM bypass.
- No lossless claim: audio is sourced from the best match on YouTube via `ytsearch1`.
- No new database, background service, or frontend dependency.
- No redesign of the existing queue, history, appearance, or update UI.
- No push, tag, or GitHub publish.

## Capability map

### 1. Music metadata resolver (backend)

- Detect `open.spotify.com/{track,album,playlist}/...` and `music.apple.com/...`.
- Fetch only the public embed/oEmbed/OpenGraph pages for those fixed hosts with `httpx`; validate every extracted cover URL before downloading it.
- Parse:
  - Spotify: `__NEXT_DATA__` entity JSON; fall back to oEmbed for single tracks.
  - Apple Music: `serialized-server-data` JSON; fall back to OpenGraph tags.
- Normalize to a collection:
  - `title`, `artist`, `album`, `thumbnail`, `media_type` (`track|album|playlist`);
  - entries with `url`, `title`, `artist`, `album`, `track_number`, `duration`, `thumbnail`, `platform`, `media_type="audio"`, and `search_query`.
- Query format: `{artist} - {title} official audio`.
- No tracklist means a clean user-facing error, not a yt-dlp fallback.

### 2. yt-dlp bridge and FFmpeg tagging

- `download_media` accepts `search_query` and music metadata. When set, it downloads `ytsearch1:<query>` with `bestaudio`.
- After conversion, embed `title`, `artist`, `album`, and `track_number`; attach cover art for mp3/m4a/flac when FFmpeg supports it.
- Cover fetch is best-effort; a cover failure must not lose the audio file. Metadata mux failure falls back to the untagged file and is reported in the job error rather than silently deleting it.
- `download_media` keeps its `(path, title)` return contract.

### 3. Playlist/album subfolders

- Queue items carry `playlist_title`, `track_number`, and `save_in_subfolder`.
- Destination: `<save_dir>/<sanitized playlist title>/`.
- Names use the audio template. Playlist items without a `{track}` token still get a zero-padded `NN - ` prefix.
- Folder names strip path separators, reserved characters, and trailing dots/spaces. The resolved destination must remain inside `save_dir`.
- `Open folder` and Electron drag-and-drop continue to receive the exact file path and pass the existing allowed-root check.

### 4. Audio filename template

Presets:

- `{track} - {artist} - {title}`
- `{artist} - {title}` (default)
- `{title} ({artist})`
- `{title}`

- Stored with existing settings (`audioFilenameTemplate`) and synced to the backend as `audio_filename_template`.
- Unknown tokens are removed; missing values collapse separators instead of leaving ` - `.
- Illegal Windows characters are stripped. Existing files keep the `(1)`, `(2)` suffix behavior.
- Applies to queue audio downloads, Spotify/Apple bridge output, and quick-fetch audio.

### 5. Concurrency and batch UI

- Default concurrency changes from `2` to `3`; saved user values remain unchanged.
- Settings shows a `1 2 3 4 5` segmented control instead of the select.
- Multi-link input splits on whitespace and commas.
- Preview shows a scrollable selector, `Select all` / `Select none`, `Selected X/Y`, a **Save playlist in subfolder** switch, and one **Download Selected (N)** action.
- Platform pills add Spotify, Apple Music, Twitch, Bilibili, Kick, Reddit, Pinterest, Vimeo, and Bandcamp.

### 6. Creator sites

- No restrictive domain allowlist is introduced; yt-dlp remains the universal extractor.
- Platform detection covers Twitch clips/VODs, Kick, Bilibili, Reddit, Pinterest, Vimeo, SoundCloud, and Bandcamp.
- Pinterest pins without a video stream fall back to the highest-resolution OpenGraph image, downloaded through the existing photo pipeline.

## Acceptance criteria

- `POST /api/info` returns playlist entries for a Spotify playlist, album, and Apple Music collection, and a single tagged entry for a track.
- Selecting three items and choosing **Download Selected** creates three jobs that respect the concurrency cap.
- A playlist download lands in `Save folder/<Playlist title>/` with `NN - ...` names; a single track lands directly in the save folder.
- Each of the four templates produces the expected filename for full and partial metadata, with illegal characters stripped.
- Spotify/Apple audio files contain title/artist/album tags; cover art is attached where the container allows it.
- Pinterest image pins preview and download at the highest available image size.
- Existing v0.5.0 guardrails remain intact: `ud_appearance_v1`, `100/115/125` scale, `100vh` sidebar, menu disabled on `Alt`, `Ctrl+A/C/V/X`, `Ctrl+Shift+D`.

## Risks

- Spotify/Apple embed markup is unofficial and can change; parsers fail closed with a readable error and a single oEmbed/OG fallback.
- `ytsearch1` can match a remix or live version. The query biases toward "official audio"; users see the resolved video title in history.
- Cover embedding differs by container; metadata tags are always written, cover art is best-effort.
- Apple playlists sometimes omit per-track URLs; those entries use `search_query` and never fetch arbitrary user-supplied hosts.
- Dynamic semaphore replacement can briefly exceed a reduced cap while old downloads finish. Existing downloads are never killed.
