## 1. Problem and Outcome

Current pain points:

- **History & Queue are hard to manage at scale.** With dozens of history entries there is no search, no filter, and no delete action. The queue cannot pause/resume, cannot retry failures, and cannot limit how many downloads run at once.
- **Playlists and multiple links are not supported.** Users must paste one link and download one clip at a time.
- **Errors and installer size are opaque.** A 403 or dropped connection forces guesswork. The installer is large (~244 MB `.exe` / ~312 MB `.zip`) and `electron-updater` is scaffolded but not wired to GitHub Releases.

Outcome in v0.6.0:

- Search, filter, delete one entry, and clear all history immediately.
- Queue supports Pause / Resume / Retry / Clear finished and Max Concurrent Downloads (1–5).
- Paste a playlist or multiple links, preview the entries, and enqueue only the selected clips.
- Transient network failures auto-retry, and errors carry actionable guidance (for example, a shortcut to Browser Cookies when a 403 occurs).
- Smaller Python/FFmpeg bundle, faster startup polling, GitHub Releases updater configuration, and an installed NSIS smoke test.

## 2. Scope and Non-Goals

### In scope (must-haves)

- **A1:** History search, platform/media filter, single-item delete, clear all history.
- **A2:** Playlist and batch URL inspection with selective enqueueing.
- **A3:** Queue pause, resume (`yt-dlp --continue` behavior), retry failed, clear finished, max concurrency (1–5).
- **B1:** PyInstaller / FFmpeg bundle diet and faster backend cold-start polling.
- **B2:** Transient network auto-retry and actionable error diagnostics (403, cookie hints, rate limit).
- **B3:** GitHub Releases publish config in `desktop/package.json`, in-app "Check for App Updates", and an NSIS installed-build smoke test.

### Explicit non-goals

- No timeline / waveform video editor.
- No external UI or state library. Keep pure CSS tokens in `globals.css` and `ud_appearance_v1` in `frontend/src/lib/appearance.ts`.
- No native Electron menu (`Menu.setApplicationMenu(null)` stays).
- No cross-platform port. Windows 11 desktop only.
- No `git push`, `git tag`, or GitHub publish without separate user approval.

- Top toolbar: Search field (min-height 40px), platform/media filter pills (All, Video, Audio, Images, and supported platforms), and a Clear history button.
- Clear history uses an inline two-step "Confirm clear?" state instead of a modal.

### Queue (`DownloadCard.tsx` / queue view)

- Active row: Pause and Cancel.
- Paused row: amber "Paused" badge plus Resume and Cancel.
- Error row: short cause plus guidance (for example "403 Forbidden — try enabling Browser Cookies in Settings"), Retry, and **Open Settings**.
- Queue header: **Clear finished** and an active counter such as `2 / 3 active`.

### Preview (`PreviewCard.tsx` for playlist / batch)

- Playlist or multiple pasted links show a scrollable entry list (`max-height: 260px`) with Select All / None, a Selected counter (`5/12`), and **Enqueue Selected (5)**.
- Narrow viewports keep controls wrapping and usable at 820×620 and 125% scale.

## 6. Technical Approach

### Backend (FastAPI / `extractor.py` / `queue_manager.py`)

- **Concurrency:** enforce a 1–5 concurrent limit using an `asyncio.Semaphore`; expose the active limit through Settings.
- **Pause/Resume:** `POST /api/queue/{id}/pause` stops the active download and keeps `.part` files; `POST /api/queue/{id}/resume` restarts the same job with `continuedl` / `--continue` semantics.
- **Retry/Clear:** `POST /api/queue/{id}/retry` requeues a failed job; `POST /api/queue/clear-finished` removes completed items.
- **History:** persist completed items in a small JSON-backed history store; `GET /api/history`, `DELETE /api/history/{id}`, `DELETE /api/history`.
- **Playlist/Batch:** use yt-dlp `extract_flat="in_playlist"` for playlist discovery and a `/api/preview` endpoint for batch URL lists.
- **Error classifier:** map yt-dlp failures to `AUTH_403`, `COOKIE_REQUIRED`, `RATE_LIMIT`, `NETWORK_TRANSIENT`, `UNSUPPORTED_URL`, `UNKNOWN`, with user-facing guidance.

### Frontend (Next.js static export)

- Use pure CSS tokens in `globals.css`; minimum interactive target 32px and primary-button contrast ≥ 4.5:1.
- Keep `ud_appearance_v1` schema and CSS zoom behavior untouched.
- Extend `api.ts` with history, queue lifecycle, preview, and updater calls.
- Add search/filter/delete to `HistoryView.tsx`, lifecycle actions to `DownloadCard.tsx`, batch selection to `PreviewCard.tsx` / `UrlBar.tsx`, and updater/concurrency controls to `SettingsView.tsx`.

### Desktop and packaging (`desktop/main.js`, `desktop/package.json`, PyInstaller)

- Add PyInstaller `excludes` for unused standard-library modules (`tkinter`, `unittest`, `pydoc`, etc. where safe).
- Poll backend startup at 100 ms instead of 400 ms.
- Configure `build.publish` for the GitHub provider and add an `app:check-update` IPC handler.
- Expose update checking through `preload.js` and a Settings button.
- Bump `frontend/package.json`, `desktop/package.json`, and the sidebar version to `0.6.0`.

## 10. Risks and Open Questions

- **Pause on HLS/DASH:** some live or segmented streams may not resume with `--continue`; fall back to restarting that file rather than hanging.
- **GitHub updater:** until a real `v0.6.0` release is published, **Check for Updates** must report "Up to date / No published release found" safely instead of throwing.
- **Bundle diet:** validate that excluded modules are not imported by yt-dlp, curl_cffi, uvicorn, or PyInstaller hooks.
- **Existing local history:** v0.5.0 history lives only in `localStorage`; the backend store starts empty and must not make old entries reappear after deletion.
- **Installed NSIS:** the v0.5.0 release was tested mainly from `win-unpacked`; v0.6.0 must include a real installed-build smoke test.
